## 問題1：スタンプカード（ポイント）


### 1. 業務フロー（主語つき・例外つき）

```
[会員]
 1. アプリを開き、ログインする
 2. 会員メニューでスタンプ数を確認できる(有効期限も確認できる)
 2. 受け取る店舗を選ぶ（営業時間外の店は選べない）
 3. メニューを見る（カテゴリごとに商品が並ぶ／売り切れの商品は選べない）
 4. 商品を選ぶ
 5. オプションを選ぶ（サイズは 1 つだけ、トッピングは複数可、必須のものもある）
 6. 数量を決めてカートに入れる
 7. クーポンを使用するか選ぶ(スタンプ10個貯まっていた場合)
 7. カートの中身と合計金額を確認する（何度でも足したり消したりできる）
 8. 受け取り時間を選ぶ
 9. 注文を確定する  ← ここで金額が確定する
10. 支払う（外部の決済サービスへ）
11. スタンプが一つ付与される
11. 注文の状態を見ながら待つ
12. 店舗で受付番号を見せて、商品を受け取る

[店舗スタッフ]
13. 入った注文を見る
14. 調理を始める        ← ここから会員はキャンセルできない
15. できあがったら「受け取り準備完了」にする
16. 会員に渡して「受け渡し完了」にする


[例外・ルール]
 - 売り切れの商品はカートに入れられない／注文確定時にも再チェックする
 - 営業時間外の店舗には注文できない
 - 調理開始後はキャンセルできない
 - 注文したあとに商品の価格が変わっても、注文の金額は変わらない
 - 商品が販売終了になっても、過去の注文履歴は正しく表示できる
 - 注文がキャンセルされたらスタンプは付与されない
 - 1年過ぎたら1個ごとに期限切れ判定を行う
 ```

### 3. ふるい分けの表

   | 名詞 | 仕分け | 理由 |
   | ---  | --- | --- |

   | 店舗 | エンティティ | 複数あり、それぞれ独立して管理される |
   | 営業時間 | 属性 | 店舗の一部（開店時刻・閉店時刻）|
   | カテゴリ | エンティティ| 表示順を持ち、本部が管理する。商品がぶら下がる|

   | 価格 | エンティティ | 590 円は 590 円。区別する意味がない |
   | オプション（サイズ / トッピング）| エンティティ | 「選択肢のまとまり」と「1 つの選択肢」の 2 階層。商品から参照される |
   | セット | 対象外（＝商品の一種）| 「セット」も 1 つの商品として扱い、中身の選択はオプションで表現する|

### 6. 判断の記録（迷ったところと、その決着。02_BURGER_DOMAIN の「設計上の論点」と同じ形式で）
#### 「いま何個たまっているか」を数値として保存するか、押した記録（履歴）から数え上げるか。 どちらにも利点と欠点があります。第2部 04章 総合問題1 の「状態と履歴を分ける」を思い出してください。
      押した履歴から数え上げる
      キャンセルで取り消しが起きたり、使用済み10個を区別したりする必要があるから、
      数値1つでは表せない。だから1個ずつの記録（履歴）で持つ

#### 「10個たまったら無料」の 無料になった1回 は、何として記録されるか。次に見たとき「使用済みの10個」と「たまり始めた新しい1個」を区別できるか。
      無料になった1回はクーポン1つ分としてカウントする
      次に見た時は使用ずみ1個としてカウントし、たまり始めた新しい１個と区別する

#### 有効期限「最後の注文から1年」は、どのタイミングで、どう判定するか。期限切れを表す状態を持つのか、日付から計算するのか。
     日付から計算する
     その注文の日付から１年経ったらそのスタンプは期限切れと判定する

#### 注文がキャンセルされたら、スタンプはどうなるか（要求に書かれていません。あなたの判断と、その理由を書いてください）。
     支払いがあった時点でスタンプは付与して、その後注文キャンセルになったら、
     取り消しをする
     1個ずつ記録で持つから、付与した1個を名指しで"取り消し"として印を付けられる。
     数値を1減らすのではなく、取り消しの記録を残す

#### クーポンをエンティティにするか値オブジェクトして扱うか
     今回の要件では値オブジェクトで足りるため、値オブジェクトにする。
     (有効期限や追跡の必要がないため)
     ただし実務で有効期限や使用先の追跡が必要になることもあるため、必要があれば、
     エンティティに昇格させる
