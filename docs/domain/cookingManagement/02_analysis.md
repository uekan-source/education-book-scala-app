# 問題2：店舗スタッフ向けの調理管理 — 思考過程（メモ・提出しない）

## 名詞と動詞

**名詞**：
会員、店舗スタッフ、店舗、タブレット、メニュー、商品、材料、
注文、注文の一覧、注文の状態、受け取り時間、支払い、
受付、調理中、受取準備完了、受渡し完了、キャンセル、未受け取り、
売り切れ、閉店、混雑

**動詞**：
注文する、支払う、見る、並べ替える、選ぶ、
調理を開始する、できあがりにする、渡す、受渡し完了にする、
未受け取りにする、売り切れにする、切れる、
進める、飛ばす、戻す、変える、影響する、続行する

動詞を 2 つに分けます。

| 種類 | 動詞 | 行き先 |
|---|---|---|
| **状態を変える** | 調理を開始する | `Order.Status` の遷移（受付 → 調理中） |
| **状態を変える** | できあがりにする | `Order.Status` の遷移（調理中 → 受取準備完了） |
| **状態を変える** | 受渡し完了にする | `Order.Status` の遷移（受取準備完了 → 受渡し完了） |
| **状態を変える** | 未受け取りにする | `Order.Status` の遷移（受取準備完了 → 未受け取り）※値を追加 |
| **状態を変える** | 店舗キャンセルにする | `Order.Status` の遷移（受付／調理中 → 店舗キャンセル）※値を追加 |
| **状態を変える** | キャンセル理由を書く | `Order` の備考欄に書く（UPDATE）※列を追加 |
| **状態を変える** | 売り切れにする | `ShopMenuStock.Status` の遷移（提供可 → 売り切れ） |
| **値を返す** | 受け取り時間の近い順に取得する | モデル／リポジトリのメソッド。**保存しない。列は増やさない** |

拾った動詞のうち、`注文する` `支払う` `見る` は既存の `sales` で完結するため表から落とす。
`切れる` `進める` `飛ばす` `戻す` `影響する` `続行する` は操作ではなく遷移の制約の記述なので、
EntityModel の「型では守れない決めごと」に書く。

## ふるい分け

| 名詞 | 仕分け | 理由 |
|---|---|---|
| 会員 | **既存エンティティ**（`User`） | 新しく作らない |
| 店舗スタッフ | **対象外** | 操作する人だが、**誰が操作したかを記録しない**（①で確認済み）ためモデルに現れない。ログイン・権限も今回作らない |
| 店舗 | **既存エンティティ**（`Shop`） | 新しく作らない |
| タブレット | **対象外（業務の外）** | 実装の器。モデルの形が変わらない |
| メニュー | **既存エンティティ**（`MenuItem`） | 「メニュー」「品目」は商品に統一済み |
| 商品 | **既存エンティティ**（`MenuItem`） | 売り切れの対象。持ち方は変わらない |
| 材料 | **対象外（業務の外）** | 在庫数を管理しない。スタッフが目視で判断し、商品を売り切れにするだけ |
| 注文 | **既存エンティティ**（`Order`） | 新しく作らない |
| 注文の一覧 | **対象外（型B：一種）** | `Order` の一種。店舗と状態で絞った結果 |
| 注文の状態 | **既存の属性**（`Order.Status`） | 注文の一部。**今回、値を 1 つ追加する** |
| 受け取り時間 | **既存の属性**（`Order`） | 並び替えに使うだけ。持ち方は変わらない |
| 支払い | **既存エンティティ**（`Payment`） | 新しく作らない |
| 受付 | **対象外**（`Order.Status` の値） | 状態の 1 つ。既存の値で足りる |
| 調理中 | **対象外**（`Order.Status` の値） | 状態の 1 つ。既存の値で足りる |
| 受取準備完了 | **対象外**（`Order.Status` の値） | 状態の 1 つ。既存の値で足りる |
| 受渡し完了 | **対象外**（`Order.Status` の値） | 状態の 1 つ。既存の値で足りる |
| キャンセル（会員都合） | **対象外**（`Order.Status` の値） | 状態の 1 つ。既存の `IS_CANCELED` を `IS_CANCELED_BY_USER` に改名する |
| 未受け取り | **対象外**（`Order.Status` の値） | 状態の 1 つ。**既存の値に無いので追加する** |
| 店舗キャンセル | **対象外**（`Order.Status` の値） | 状態の 1 つ。**既存の値に無いので追加する**。会員都合と分けて測るため |
| キャンセル理由 | **属性** | `Order` の列。会員向け・店舗向けの 2 つを持つ |
| 売り切れ | **既存エンティティ**（`ShopMenuStock`） | 店舗 × 商品の状態。**今回の操作対象** |
| 閉店 | **対象外** | 閉店時刻を判定しない。スタッフがボタンを押したときが「閉店時」（①で確認済み） |
| 混雑 | **対象外（スコープ外）** | 混雑の自動判定はしない（①で確認済み）。スタッフが並び替えるだけ |

### ふるい分けで確認したこと

- **新規エンティティは 0 件。** 問題文の「新しく作る必要はありません」と整合する
- **追加するのは `Order.Status` の値 1 つだけ**（`未受け取り`）
- **対象外が 12 件**（うち 6 件は `Order.Status` の値）
- **`店舗スタッフ` を対象外にしたのが今回の要点。**「操作する人 ≠ エンティティ」。
  誰が操作したかを記録しないなら、モデルに現れない。
  `User`（会員）が必要なのは `Order.userId` として記録されるから
- **`受け取り時間` は既存の属性。** 問題文の問い3（並び替えだけの話か）への答えは
  「持たせる必要なし。既にある。並び替えだけ」

### 仕分けの書き方について

仕分けは 4 種類固定ではなく、「既存」を付けて組み合わせる。

| 書き方 | 意味 |
|---|---|
| エンティティ | 新しく作る |
| **既存エンティティ** | すでにある。変更しない |
| 属性 | 新しく足す |
| **既存の属性** | すでにある（今回変更することもある） |
| 対象外 | **モデルに現れない** |

`Order.Status` のように実在するものを「対象外」に入れると
**「モデルに現れない」という誤った意味**になるので、書き分ける。

## ユビキタス言語（候補）

新規エンティティが 0 件なので、追加する呼称も少ない。
**ただし「呼び方の衝突」が 2 つ見つかった。** ④の本題は同義語の統一なので、ここが今回の中身。

### 追加を申請する呼称

| 日本語 | 英語名 | 意味 | 多重度・備考 |
|---|---|---|---|
| 未受け取り | `Order.Status.IS_UNCLAIMED` | 受取準備完了のまま閉店を迎え、会員が受け取りに来なかった注文 | `Order.Status` の値。`code = -3` |
| 会員キャンセル | `Order.Status.IS_CANCELED_BY_USER` | 会員の都合で取り消された注文 | `Order.Status` の値。`code = -1` |
| 店舗キャンセル | `Order.Status.IS_CANCELED_BY_SHOP` | 材料切れなど店舗の都合で取り消された注文 | `Order.Status` の値。`code = -2` |
| 会員向け備考 | `Order.noteForUser` | 会員に見せる理由。キャンセル・未受け取りの説明 | `Order` の列（任意） |
| 店舗向け備考 | `Order.noteForShop` | 店舗内部のメモ。会員には見せない | `Order` の列（任意） |

### 衝突していた呼び方（統一する）

| 業務で使われている言葉 | 統一後の呼称 | なぜ |
|---|---|---|
| **できあがり**（要求文・タブレットのボタン） | **受取準備完了**（`IS_READY`） | 同じ状態を指す。既存の呼称に合わせる |
| **調理中ボタンを押す** | **調理を開始する** | 「ボタン」は画面の話。業務の操作名にそろえる |

> ⚠️ 要求文は「『調理中』『**できあがり**』を押していく」と書いているが、
> 既存の `Order.Status` には「**受取準備完了**」がある。**同じものを 2 つの言葉で呼んでいる。**
> ボタンのラベルは「できあがり」でよいが、**仕様書・コード・会話では「受取準備完了」に統一する。**

### 「未受け取り」と「キャンセル」を区別する

| 呼称 | 何が起きたか | 支払い | 言い換えない |
|---|---|---|---|
| **キャンセル** | 注文が取り消された（調理開始前） | 返金する | 「取消」「破棄」 |
| **未受け取り** | 調理済みだが、会員が取りに来なかった | **返金しない。売上は立ったまま** | 「キャンセル」「破棄」「放置」 |

**どちらも「渡さずに終わった注文」だが、原因と会計上の扱いが違う。**
「来なかった注文をキャンセルにする」と言われたら、必ずどちらか聞き返す。

## 名前を並べて確認する

**新しいテーブルもクラスも作らないので、並べるものは `Order.Status` の値だけ。**

### 既存の値に混ぜて並べる

```scala
enum Status(val code: Int) extends EnumStatus[Int]:
  case IS_ACCEPTED         extends Status(code =  100) // 受付
  case IS_COOKING          extends Status(code =  200) // 調理中
  case IS_READY            extends Status(code =  300) // 受取準備完了
  case IS_DELIVERED        extends Status(code =  400) // 受渡し完了
  case IS_CANCELED_BY_USER extends Status(code =   -1) // 会員によるキャンセル  ← 今回追加
  case IS_CANCELED_BY_SHOP extends Status(code =   -2) // 店舗によるキャンセル  ← 今回追加
  case IS_UNCLAIMED        extends Status(code =   -3) // 未受け取り            ← 今回追加
```

見るポイント。

- **`IS_` 接頭辞は既存にそろえる。** 雛形の `User.Status`（`IS_ACTIVE` / `IS_INACTIVE`）と同じ流儀
- **符号が意味を持つ。** 正 ＝ 受け渡しまで正常に進む流れ、負 ＝ 商品が渡らずに終わった。
  `code > 0` で「正常に完了したか」を判定できる
- **正の値は 100 刻み。** 間に状態が増えても `250` で挿入できる
- **0 は使わない。** 「何も設定されていない」と区別できなくなる
- **値は業務フローの順に並べる。** 名前順ではなく**遷移の順序**で並べるほうが読める。
  負の終端状態は末尾

### 候補の評価

| 候補 | ① 役割差 | ② 意味の正確さ | ④ 業務に通じる | ⑤ 長さ | **総合** |
|---|:-:|:-:|:-:|:-:|:-:|
| **`IS_UNCLAIMED`** | 9 | 9 | 8 | 9 | **9** |
| `IS_NOT_PICKED_UP` | 9 | 9 | 9 | **4** | **7** |
| `IS_NO_SHOW` | 7 | 7 | 8 | 9 | **6** |
| `IS_ABANDONED` | 6 | **5** | 5 | 8 | **5** |
| `IS_EXPIRED` | **4** | **4** | 4 | 9 | **4** |

却下理由。

| 候補 | なぜ採らなかったか |
|---|---|
| `IS_NOT_PICKED_UP` | 意味は最も正確だが、**否定形 + 3 語で長い。** enum 値としてコードに何度も出てくる |
| `IS_NO_SHOW` | 「客が来なかった」を指す語だが、**注文の状態ではなく会員の行動**を表している。主語がズレる |
| `IS_ABANDONED` | 「放棄された」。会員が意図的に捨てたように読める。**カートの離脱と紛らわしい** |
| `IS_EXPIRED` | 期限切れ。**受け取り期限を設けていない**ので、何が expire したのか説明できない |

**`UNCLAIMED` は「引き取られていない」。** 荷物や忘れ物の文脈で使われる語で、
「作ったが渡していない」という状態に素直に対応する。
**判断が変わる条件：** 将来「受け取り期限を過ぎたら自動で未受け取りにする」なら
`IS_EXPIRED` にも意味が出る。今回は期限を設けないので不要。

## 判定フロー（③のメモより）

```
名詞を 1 つ取る
  ↓
【第 1 問】そもそもモデルにするか？
  → しない → 対象外（業務の外 / 型A：動詞だった / 型B：一種だった / 計算できる）
  → する ↓
【第 2 問】単独で存在するか、何かの一部か？
  → 一部 → 属性
  → 単独 ↓
【第 3 問】中身が同じでも区別するか？ 履歴を追うか？
  → はい → エンティティ
  → いいえ → 値オブジェクト
```

**「既存だから対象外」ではない。** 判定は「今回追加・変更するモデルが、それを参照するか」。
