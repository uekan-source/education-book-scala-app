# 問題2：店舗スタッフ向けの調理管理 — 要件定義
 
## 受け取った要求
 
「店舗のタブレットで、入った注文を見られるようにしたい。
『調理中』『できあがり』を押していく。
混んでいるときは、受け取り時間の近いものから作りたい。
急に材料が切れたら、その場で商品を売り切れにしたい。
お客さんが来なかった注文は、閉店時に一括で『未受け取り』として片付けたい。」
 
## 確認したいこと（質問リスト）
 
| 質問 | 今回の回答（仮） |
|---|---|
| 「未受け取り」はキャンセルとは別の状態として扱うか。返金や売上の扱いはどうするか | キャンセルとは別の状態とする。すでに支払い済みなので返金はせず、売上は立ったままとする |
| 「混んでいるとき」は、システムが混雑を判定して自動で並び順を変えるのか。それともスタッフが必要に応じて並び替えるだけか | スタッフが並び替えるだけ。混雑の自動判定はしない |
| 閉店時の一括処理は、スタッフがボタンを押すのか、時刻で自動実行するのか。対象は「受取準備完了」のまま残った注文だけでよいか | スタッフがボタンを押す。対象は「受取準備完了」のまま残った注文のみ |
| 状態を押し間違えたとき、前の状態に戻せる必要があるか（例：調理中 → 受付） | 戻せなくてよい。押し間違えは運用でカバーする |
| スタッフのログイン・権限・シフト管理は今回作るか | 作らない。タブレットは店舗に設置され、開いた人が誰でも操作できる前提とする |
 
## 業務フロー
 
```
[会員]
 1. メニューを見て注文し、支払う
 
[店舗スタッフ]
 2. 店舗のタブレットで、入った注文の一覧を見る
 3. 受け取り時間の近い順に並べ替えて見る
 4. 注文を選び、「調理中」を押して調理を開始する
 5. できあがったら「できあがり」を押す
 6. 来店した会員に商品を渡し、「受渡し完了」にする
 7. 来店しなかった注文は、閉店時にまとめて「未受け取り」にする
 
[例外・ルール]
 - 材料が切れたら、スタッフがその商品をその場で売り切れにする
 - 状態は「受付 → 調理中 → 受取準備完了 → 受渡し完了」の順に進み、飛ばすことも前に戻すこともできない
 - キャンセル済み・受渡し完了・未受け取りの注文は、それ以上状態を変えられない
 - 「未受け取り」にできるのは、受取準備完了のまま閉店を迎えた注文だけ
 - 売り切れは店舗ごとに設定され、他店舗には影響しない
 - 売り切れにしても、すでに確定した注文には影響しない（調理は続行する）
```
