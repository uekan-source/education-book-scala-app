# 処方箋送信アプリ — 思考過程（メモ・提出しない）

## アクター洗い出し（段階 1。2026-08-19）

エージェント（裏仕様を知らない別の Claude）に候補を数え上げさせ、採否を自分で決めた。
⚠ 12 件は 3 つずつの一括確認で処理した（`Q18`〜`Q27`、＋「持たない」判断 4 件）。

### 7 つの問い

| # | 問い | 答え |
|---|---|---|
| 1 | このデータを最初に作るのは誰か | **患者**（送信・処方箋画像・受け取り希望）／ **本部**（薬価・医薬品・店舗マスタ）／ **レセコン**（調剤明細を連携で入れる）。医療機関は処方箋そのものを作るが、システム外 |
| 2 | 日常的に変更するのは誰か | **薬局スタッフ**（状態の操作が主な書き込み）。患者も再送・取り消しで変更する |
| 3 | 止める・承認する権限を持つのは誰か | **薬局スタッフ**（差し戻し・未来店・廃棄）。多段の承認フローは要求に無い |
| 4 | お金を受け取る／払うのは誰か | 患者が窓口で払い、薬局が受け取る。アプリでは決済しない（`Q4`）。計算はレセコン、検算は本部 |
| 5 | 集計を見るのは誰か | **本部**（金額の検算・店舗横断の分析・月次件数。金額と件数だけで、画像は見えない `Q26`） |
| 6 | 問い合わせを受けるのは誰か | **薬局スタッフ**（患者との電話 `Q7` `Q11`）。本部のコールセンターは要求に無い |
| 7 | 人ではないが動くものは何か | **レセコン**（外部・店舗ごとに別個体）。**画像削除バッチ**（`Q25`。仕事はこれだけ）。通知の配信基盤は保留 |

### 6 類型の確認

| 類型 | いる／いない | 理由 |
|---|---|---|
| 運営者・本部 | **いる** | 要求文が明示。薬価管理＋検算＋横断分析＋店舗マスタ（`Q22`） |
| 承認者・監査 | **専任はいない** | 承認を待つ記述が無い。ただし個別指導に耐える記録（日付・操作者つき）は要る（`Q19` `Q27`） |
| CS・サポート | **いない。薬局スタッフが兼任** | 問い合わせ経路は全部 薬局↔患者 の電話 |
| 経営・分析 | **本部が兼ねる** | 所持物 0。読むだけ |
| バッチ・スケジューラ | **いる。仕事は画像の 90 日削除だけ**（`Q25`） | 未来店・廃棄・期限切れは全部スタッフ（`Q17`）。状態遷移にバッチは触らない |
| 外部サービス | **レセコン** | `Q6` `Q13` で境界確定。医療機関はシステム外（連携すらしない）。通知の配信基盤は保留 |

**アクターは 3 人（患者・薬局スタッフ・本部）＋ 外部（レセコン、医療機関）＋ 画像削除バッチ。** コンテキスト候補は 3 つ。

### 持たないと決めたもの（→ 03 の付録A 行き）

| 概念 | 判断 | 理由 |
|---|---|---|
| 通知の送り先（デバイストークン） | **保留**（段階 8 で戻る） | 手段を聞いていない |
| 患者への電話連絡の記録 | **持たない** | 電話の中身はシステムの外。差し戻した／しなかったという結果だけ残る |
| 検算の結果・差異 | **持たない** | 検算は本部が読んでやること |
| レセコン連携の受信記録 | **持たない** | 連携の信頼性は実装・インフラの話と割り切る |
| 交付日 | **持たない** | `Q24`。期限判定は目視で足りる。打ち間違いは誤判定の元 |
| 差し戻し理由のマスタ化 | **しない**（enum 側） | `Q23`。増えるのは年単位でまれ、増やすときはアプリ改修とセット |

### 論点の種（→ 03 の付録B 候補。却下した案を残す）

| 論点 | 採らなかった案 | 却下の理由（`01` の Q に詳細） |
|---|---|---|
| 差し戻し理由の粒度 | 「扱えない薬」と「在庫切れ」を統合する | 恒常と一時で対応が違う（即返す vs 電話で意向確認）。`Q29` |
| 差し戻しの持ち方 | 最新の理由だけ持つ（履歴にしない） | クレーム・個別指導・傾向分析で経緯が要る。`Q20` `Q30` |
| 後始末の内訳 | 戻した／廃棄したを区分で持つ | システムの関心はロスの把握で、内訳は現場の作業。`Q28` |
| **送信の持ち主**（未決） | ①患者の依頼と薬局の案件に割る ／ ②「作る人 ≠ 持ち主」で 1 つのまま薬局の所持物にする | **段階 7 で決める。** はみ出しチェックで浮上。判定の 2 問（消えたら誰が困るか＝薬局がロス・監査で困る ／ 変更権限＝局面で入れ替わる）が割れている |

### はみ出しチェック（2026-08-19 実施）

| チェック | 結果 | 対応 |
|---|---|---|
| 2 人が同じものを対等に変更する | **「送信」に当たった。** 患者（送る・再送・取り消し）とスタッフ（仮受付・差し戻し・正式受付・受け渡し・未来店・取り置き終了）が**交互に**触る。ただし「対等」かは怪しい──触る局面が違い、差し戻し → 再送のループで行き来する。①患者の依頼と薬局の案件に**割る**のか、②バーガーの `Order` と同じ**「作る人 ≠ 持ち主」で 1 つのまま**なのか | **段階 7（概念を配る）の主論点。** 論点の種に追加した |
| | 処方箋画像は患者が作りバッチが消すが、局面が違うだけで対等ではない | 問題なし |
| 所持物が極端に多いアクター | スタッフが 6 件で最多。ただしうち 5 件は**「送信に起きたことの記録」**（仮受付・正式受付・受け渡し・未来店・取り置き終了）で、段階 5 で送信の属性（時刻・操作者）に畳まれる可能性が高い | アクターが 2 人に分かれている兆候ではない。段階 5 で「エンティティか属性か」を判定 |
| 5 分以上迷ったもの | まだ無い。ただし**すでに 1 件割れている**：アカウントと患者（`Q18` で「持ち主と患者は別人でよい」→ 2 概念に確定）。「1 つの言葉が 2 つのものを指していた」型 | 割れ済み。段階 5 で 2 エンティティとして扱う |
