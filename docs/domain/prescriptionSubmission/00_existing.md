# 処方箋送信 — 既存システム（演習の与件）

**この演習は「既存システムへの 1 機能追加」の形にした**（研修のスタンプカード追加と同じスコープ感）。このファイルが、研修における雛形モデル・`02_BURGER_DOMAIN` に相当する与件。

2026-08-19 のスコープ切り替えで、`Q1`〜`Q42` の回答のうち**土台側のもの**をここへ移した。出どころの `Q` 番号は残してある。**演習範囲（`01_requirements.md`）は「送信の一生」だけ。**

## 想定規模（`Q16`）

- 180 店舗、全店で一斉導入。3〜5 年で 200 店舗程度
- 送信 1 店舗 1 日 20〜60 件（全体 4,000〜10,000 件/日）→ 普及して 100 件/日/店
- アカウント約 30 万 → 3 年で 50 万

## 既存の仕組みと決めごと

| 仕組み | 決めごと | 出どころ |
|---|---|---|
| **アカウントと患者** | 電話番号 ＋ SMS 認証（メール不使用）。**1 アカウントに患者を最大 6 名**（本人＋家族）。**アカウントの持ち主と患者は別人でよい。** 患者ごとに氏名（漢字・カナ）・生年月日・性別。**保険証の情報は持たない**（窓口で確認）。退会・患者削除は進行中の送信が無ければ可能で、過去の記録は氏名ごと 5 年残る | `Q18` `Q38` |
| **スタッフと権限** | 個人アカウント・所属店舗つき。**すべての状態操作に、誰がやったかが記録される。** 他店の送信は見えない。**誤操作は記録を消さず、訂正の操作を重ねて戻す**仕組みがある | `Q19` `Q26` `Q36` |
| **店舗マスタ・営業時間** | 本部が管理。店舗では変えられない。新店は年 1〜2、営業時間変更は月数件 | `Q22` |
| **医薬品・薬価マスタ** | 約 15,000 品目。**薬価は「いつから適用するか」を指定して登録し、過去を残す。** 事前登録できる（年 1 回 4/1・数千品目・本部 2 名）。適用開始前は訂正・削除自由、開始後は訂正の登録を重ねる | `Q16` `Q21` `Q39` |
| **店舗ごとの取扱い設定** | 店舗ごとに扱わない医薬品の設定がある（麻薬・冷所品・特殊な剤形など。店舗あたり 50〜200 品目）。差し戻し理由「この薬局で扱えない薬」の判定の裏付け | 既存仕様 |
| **レセコン連携** | レセコンは外部で、店舗ごとに導入済み（180 店舗でばらばら）。**処方内容の入力と会計の計算はレセコン。調剤明細は会計の確定時に連携で入り**、このシステムが 5 年保存する | `Q4` `Q6` `Q13` |
| **通知の基盤** | プッシュ通知を送る仕組みは既存。**送信履歴は持たない** | 既存仕様 |
| **保存と監査** | 記録は最低 5 年。日付・操作者つきで、厚生局の個別指導に出せる形 | `Q27` |
| **アクセス境界** | 患者＝アカウント単位（登録患者全員分）／スタッフ＝所属店舗のみ／本部＝金額・件数のみ（画像は見えない） | `Q26` |

## この演習では扱わない（範囲外）

- 本部の検算・店舗横断分析（既存または別機能とする）
- アプリ内決済／お薬手帳・服薬履歴（2 周目候補）／在庫管理／疑義照会そのものの記録／電子処方箋／領収書の電子化／配達
