# 問題1：スタンプカード（ポイント） - 思考過程(メモ・提出しない)


##  名詞と動詞

**名詞**：会員、店舗、注文、注文明細、支払い、スタンプ、クーポン、付与日、スタンプ数、有効なスタンプ、失効したスタンプ、消費済み、無料特典、有効期限、キャンセル、専用画面

**動詞**：ログインする、確認する、支払う、キャンセルする、選ぶ、
スタンプを付与する、スタンプを取り消す、クーポンを発行する、クーポンを使用する、
数え上げる、除外する、失効する、判定する
| 種類 | 動詞 | 行き先 |
|---|---|---|
| **状態を変える** | スタンプを付与する | スタンプを **1 行足す**（新しい状態遷移は増えない） |
| **状態を変える** | クーポンを発行する | クーポンを **1 行足す**（新しい状態遷移は増えない） |
| **状態を変える** | スタンプにクーポンを紐付ける | 消費の事実として、スタンプに **クーポンへの参照を書く**（一度書いたら戻さない） |
| **状態を変える** | クーポンを使用する | **未使用 → 使用済み の状態遷移**（今回唯一の遷移） |
| **状態を変える** | スタンプを取り消す | キャンセル時。付与済みスタンプを無効化する |
| **値を返す** | 有効なスタンプ数を数え上げる | モデルのメソッド。保存しない |
| **値を返す** | そのスタンプが失効しているか判定する | モデルのメソッド。付与日と現在日時から算出 |
| **値を返す** | 使えるクーポンがあるか判定する | モデルのメソッド |


##  ふるい分け
  （エンティティ / 値オブジェクト / ただの属性 / 対象外）

| 名詞 | 仕分け | 理由 |
|---|---|---|
| 会員 | **既存エンティティ**（`User`） | 雛形をそのまま使う。新しく作らない |
| 店舗 | **既存エンティティ**（`Shop`） | 新しく作らない |
| 注文 | **既存エンティティ**（`Order`） | スタンプを押すきっかけ。参照するだけ |
| 注文明細 | **既存エンティティ** | 無料対象の商品を特定するのに使う。持ち方は変わらない |
| 支払い | **既存エンティティ** | 付与のタイミング（支払い確定）を知るのに使う |
| スタンプ | **エンティティ（新規）** | 1 個ずつ識別する。どの注文で押されたか、どのクーポンに消費されたかを追跡し、古い順に 10 個選ぶ（FIFO）必要がある |
| クーポン | **エンティティ（新規）** | 発行される・未使用/使用済みの遷移を持つ・未使用のまま複数枚持てる |
| 付与日 | 属性 | スタンプの列。**唯一保存する事実**で、失効判定の根拠になる |
| スタンプの取り消し | 属性 | キャンセル時も履歴は残す（受け入れ条件）ため、行は消さず無効の印を持つ |
| スタンプ数（保有数） | **対象外（＝計算結果）** | 保存しない。有効なスタンプの行を都度数え上げる |
| 有効なスタンプ / 失効したスタンプ | **対象外（＝計算結果）** | 保存しない。付与日と現在日時から判定する |
| 有効期限 | **対象外（＝計算結果）** | 保存しない。付与日 + 1 年で算出する。列を作らない |
| 無料特典 | **対象外** | クーポン 1 枚 = ハンバーガー 1 つ無料と固定。特典の種類を管理しない |
| キャンセル | **既存**（`Order` のステータス） | 注文のキャンセル自体は `sales` に既にある概念。新設しない |
| 専用画面 | **対象外** | 画面の話であり、業務の概念ではない |
